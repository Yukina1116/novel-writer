## 教訓(今回の運用上の学び)

- **「直した」の範囲を原因で言い切らない**: #326 は「画面高が低い」を原因としたが、Muse の「1080px でも起きた」は別の原因(テキストエリアの無制限な伸長)だった。報告の条件(高さ・状態)と修正の想定条件が食い違ったら、実機で再現して原因を確定する
- **`gh pr merge` は単独で実行する(2 回目の再発)**: 前回は `2>&1 | tail`、今回は `cd ... &&` と `| tail` を付けて pr-merge-gate に拒否された。承認は取得済みのため、そのまま `gh pr merge N --squash --delete-branch` だけを再実行して通った。最初から単独で書く(cwd はすでにプロジェクトにある)
- **ファイル名は大文字小文字違いで衝突させない**: `aiLoginNotice.ts` と `AiLoginNotice.tsx` を並べると、macOS(大文字小文字を区別しない)でも Linux CI でも `tsc` が TS1149 / TS1261 を出す。pure helper は `...Visibility.ts` のように別名にする
- **ローカルの `npm run dev` は `GCLOUD_PROJECT` を付ければ起動する**: Firebase Admin の初期化に `GCLOUD_PROJECT=novel-writer-dev` が要る(前回の「起動しない」は環境変数不足が原因)。3000 番を Docker の Open WebUI が使っている場合は `PORT=3917` で逃がす。停止は `pkill -f` が auto mode に拒否されるため、`ps` で自分の PID を特定して `kill`
- **dev の Playwright プロファイルには開発者アカウントのログインが残っている**: 未ログインの確認は `browser_run_code_unsafe` で `page.context().browser().newContext()` を使い、まっさらなコンテキストで行うとセッションを壊さない
- **レビュー指摘は不採用にも根拠を残す**: codex の P2 は、限界値(`containerHeight - 200` の余白 200px に対し案内は約 40px)と既存挙動との同根性で不採用にした。PR の Test plan と handoff の両方に理由を記録している
